# HA Tray Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A macOS menu bar app that shows the user's Home Assistant dashboard in a transient popover, logged in via a long-lived token, sidebar hidden, with the dashboard chosen by entity-state rules on each open.

**Architecture:** SwiftPM package with a pure-logic library (`HATrayCore`: rules, URLs, HA REST client, settings, keychain) covered by unit tests, and an AppKit/SwiftUI executable (`HATray`) for the status item, popover + `WKWebView`, and settings window. A shell script assembles the executable into an ad-hoc-signed `.app` bundle (no Xcode project; no signing identity exists on this machine).

**Tech Stack:** Swift 6.4 toolchain (language mode 5), macOS 14+, AppKit, SwiftUI, WebKit, Security (Keychain), ServiceManagement (`SMAppService`), `sindresorhus/KeyboardShortcuts` (SPM, from 2.0.0), XCTest.

**Spec:** `docs/superpowers/specs/2026-10-30-ha-tray-design.md`

## Global Constraints

- No Dock icon: `LSUIElement = true` in Info.plist.
- Bundle id `io.github.theak.ha-tray`, app name `HA Tray`.
- Token stored only in Keychain (service `io.github.theak.ha-tray`, account `ha-token`); all other settings in `UserDefaults`.
- Rule matches iff entity state == `"on"` exactly. First matching rule wins.
- State fetch timeout: 1.5 s total. On total failure/timeout: do not navigate (show current page, or default if nothing loaded). Late results ignored.
- Default panel size 420 × 700.
- Tests against real HA (`$HA_URL`, `$HA_TOKEN`) are read-only — never call service endpoints.
- `NSAllowsArbitraryLoads`/`NSAllowsLocalNetworking = true` in Info.plist (HA is plain HTTP on LAN).

## Verified facts about the HA frontend (current instance)

- External auth activates when `window.webkit.messageHandlers.getExternalAuth` exists (or `?external_auth=1`). Frontend posts `{callback: "externalAuthSetToken", force: Bool}`; app replies by evaluating `window.externalAuthSetToken(true, {"access_token": <token>, "expires_in": 1800})`. Revoke: handler `revokeExternalAuth`, posts `{callback: "externalAuthRevokeToken"}`; reply `window.externalAuthRevokeToken(true)`.
- Do NOT register an `externalBus` handler.
- Sidebar: `localStorage.setItem("dockedSidebar", JSON.stringify("always_hidden"))` before the frontend boots.

## Review Focus

1. HA URL entered with trailing slash or path (`http://ha:8123/`) — dashboard and API URLs must not contain `//`.
2. Dashboard path entered with/without leading slash (`/lovelace/0` vs `lovelace/0`) — both work.
3. HA unreachable when panel opens — popover appears within ~1.5 s, no navigation, no hang.
4. Invalid/expired token (401) — state fetch treated as failure; "Test connection" reports "Unauthorized (401)".
5. Entity state `unavailable`, `unknown`, `off`, `On` — none match; only `on` does.

  - `public struct HAClient { init(baseURL: URL, token: String, session: URLSession = .shared); func fetchStates(_ entityIDs: [String], timeout: TimeInterval = 1.5) async -> StateFetchResult; func testConnection() async -> Result<Void, HAError>; func allEntities(domains: Set<String>) async throws -> [String] }`
  - `public enum HAError: Error, Equatable, LocalizedError { case unauthorized, http(Int), network(String) }` — `unauthorized.errorDescription == "Unauthorized (401)"`.

- [ ] **Step 1: Failing tests** `HAURLsTests`: `dashboard(base: "http://ha:8123/", path: "/lovelace/0")` → `http://ha:8123/lovelace/0`; same with base no slash and path no slash; `api(base:"http://ha:8123/", "states/input_boolean.x")` → `http://ha:8123/api/states/input_boolean.x`.
- [ ] **Step 2: Failing tests** `HAClientTests` using a `URLProtocol` stub session:
  - `testFetchStatesParsesStateAndSendsBearer`: stub returns `{"entity_id":"input_boolean.a","state":"on"}` → `.states(["input_boolean.a":"on"])`; request header `Authorization == "Bearer tok"`.
  - `testFetch404OmitsEntity`: a→404, b→200 "on" → `.states(["b":"on"])`.
  - `testAllFailuresIsFailed`: every request errors → `.failed`.
  - `testTimeoutIsFailed`: stub delays 3 s, timeout 0.2 → `.failed` within 1 s.
  - `testConnection401`: → `.failure(.unauthorized)`.
  - `testLiveConnection` (skipped via `XCTSkipIf` unless `HA_URL`/`HA_TOKEN` set): `testConnection()` succeeds; `fetchStates(["sun.sun"])` returns `.states` containing that key.
- [ ] **Step 3:** `swift test` → FAIL.
- [ ] **Step 4:** Implement. `fetchStates` fetches concurrently (`withTaskGroup`), whole operation raced against the timeout; returns `.failed` if timed out or if every request failed (non-404 errors, 401, network), `.states` otherwise (empty entityIDs → `.states([:])`).
